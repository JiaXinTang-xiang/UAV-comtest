# 虚拟机迁移与依赖安装

本说明针对当前已经飞通的工程：Ubuntu 22.04 x86_64、ROS2 Humble、Gazebo Classic 11、PX4 v1.14.3、Micro XRCE-DDS Agent 2.4.3。新虚拟机尚未执行以下安装和飞行验证。

## 1. 选择迁移方式

**最省事：关机后克隆或导出整台现有虚拟机，再导入另一台电脑。** 系统依赖、源码、编译产物和路径一起保留，通常不用重新下载软件。导入后检查虚拟显卡、网络和时间，再按启动文档试飞。若当前环境不是虚拟机，则使用下一种方式。

**新建 Ubuntu 虚拟机：复制完整 bao 目录，安装系统依赖，重新构建。** 推荐新系统继续使用用户名 `jiaxintang`，工程放在 `/home/jiaxintang/桌面/bao`，减少路径变化。只从 GitHub 克隆的源码缺少 PX4 内部 Git 元数据，当前不能直接替代完整本地目录；详见《仓库与依赖管理》。

建议配置：4～8 个虚拟 CPU、内存 8 GB 起步（建议 16 GB）、至少 40 GB 可用磁盘空间。开启虚拟机 3D 加速，安装对应虚拟机工具。硬件配置是建议值，运行速度仍取决于宿主机。Ubuntu 24.04、ARM 虚拟机需要另做适配。

## 2. 要带走哪些文件

复制整个 `bao`，包括隐藏文件、符号链接及 PX4 内部 `.git`。重点包括：

| 内容 | 用途 |
|---|---|
| `PX4-Autopilot/`，包括递归子模块及 Git 元数据 | 定制 PX4、DDS 发布列表、Gazebo 插件和光流修复 |
| `Micro-XRCE-DDS-Agent/` | Agent 2.4.3 源码、依赖下载和本地安装 |
| `third_party/` | 本地 Micro-CDR 等依赖 |
| `px4_msgs_overlay_ws/src/` | 与当前 PX4 匹配的消息定义 |
| `uav_competition_ws/src/` | 双路线、控制、自检、世界文件和模型纹理 |
| `scripts/`、`config/`、`patches/` | 启动、参数和修复 |
| `docs/`、`logs/flight/` | 操作说明和已有飞行记录 |

不要只复制 world 文件，也不要重新下载最新版 PX4、px4_msgs 或 Agent 覆盖定制源码。`/opt/ros`、`/usr` 下的软件是系统安装，复制 `bao` 不会把它们带过去。

在旧机器停止仿真后打包（输出文件在 bao 外，避免打包自身）：

```bash
cd /home/jiaxintang/桌面
tar --exclude='bao/PX4-Autopilot/build_moved_from_old_path_*' \
  -czf "$HOME/bao-migration.tar.gz" bao
cd "$HOME"
sha256sum bao-migration.tar.gz > bao-migration.tar.gz.sha256
```

把压缩包和校验文件一起复制到新机器的家目录。新机器执行：

```bash
cd "$HOME"
sha256sum -c bao-migration.tar.gz.sha256
mkdir -p "$HOME/桌面"
tar -xzf bao-migration.tar.gz -C "$HOME/桌面"
```

用压缩包传输可保留符号链接；不要在 Windows 中解压后再复制。若目标已有 bao，先改名保存，避免两套工程混在一起。

## 3. 新 Ubuntu 22.04 安装系统依赖

以下只在**新虚拟机**执行，需要联网与 sudo。已有 ROS2 Humble 软件源时跳过添加源步骤。

### 3.1 ROS2 Humble 软件源

```bash
sudo apt update
sudo apt install -y locales software-properties-common curl gnupg
sudo locale-gen en_US.UTF-8
sudo update-locale LANG=en_US.UTF-8
export LANG=en_US.UTF-8
sudo add-apt-repository -y universe
sudo curl -fsSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key \
  -o /usr/share/keyrings/ros-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] http://packages.ros.org/ros2/ubuntu jammy main" \
  | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null
sudo apt update
```

### 3.2 ROS、Gazebo Classic 和编译库

```bash
sudo apt install -y \
  ros-humble-desktop ros-humble-gazebo-ros-pkgs \
  ros-humble-rosidl-default-generators ros-humble-rosidl-default-runtime \
  gazebo libgazebo-dev \
  build-essential cmake ninja-build git pkg-config ccache \
  python3-dev python3-pip python3-setuptools python3-wheel \
  python3-colcon-common-extensions python3-rosdep python3-empy \
  python3-yaml python3-numpy python3-jinja2 python3-lxml \
  libopencv-dev libeigen3-dev libboost-all-dev \
  protobuf-compiler libprotobuf-dev libtinyxml-dev libtinyxml2-dev \
  libasio-dev libssl-dev libspdlog-dev libfoonathan-memory-dev \
  libxml2-dev libxml2-utils qtbase5-dev \
  libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev \
  gstreamer1.0-plugins-base gstreamer1.0-plugins-good \
  gstreamer1.0-plugins-bad gstreamer1.0-libav \
  astyle file gdb unzip zip rsync bc mesa-utils
```

本工程需要命令 `gazebo --version` 显示 **11.x**。`gz-garden` 不是它的替代品。当前 PX4 的 `Tools/setup/ubuntu.sh` 在 Ubuntu 22.04 默认安装 Garden，所以不要直接运行该脚本或旧的 `scripts/install_px4_sitl.sh` 来迁移。

ROS 软件源、密钥和旧版本软件包会随时间变化；如果 apt 报找不到包，保留完整错误再处理，不要临时换成其他 Gazebo/ROS 大版本。

### 3.3 PX4 Python 依赖

在普通用户下执行。保留 Empy 3 和 NumPy 1 的兼容范围，不要使用 sudo pip：

```bash
cd "$HOME/桌面/bao"
python3 - <<'PY'
from pathlib import Path
src = Path('PX4-Autopilot/Tools/setup/requirements.txt').read_text()
# 原 requirements 中旧式 matplotlib>=3.0.* 不被新版 pip 接受。
src = src.replace('matplotlib>=3.0.*', 'matplotlib>=3.0')
Path('/tmp/bao-px4-requirements.txt').write_text(src)
Path('/tmp/bao-px4-constraints.txt').write_text(
    'empy==3.3.4\nnumpy<2\nsetuptools<70\nmatplotlib<3.8\nnunavut<3\n')
PY
python3 -m pip install --user \
  -r /tmp/bao-px4-requirements.txt -c /tmp/bao-px4-constraints.txt
```

纯 SITL 不需要 ARM 交叉编译器、NuttX 真机工具链、ArduPilot、MAVROS 或 Java/jMAVSim。QGroundControl 可选；录屏软件按比赛要求另外准备。

## 4. 编译顺序与路径

在新虚拟机新开终端，只 source 系统 ROS，再构建消息包和业务节点。不要 source 搬来的旧工作空间后编译；CMake 缓存、Python 入口脚本和 ROS 环境文件可能保留原机器绝对路径。

### 4.1 消息包与业务节点

下面使用英文路径构建消息，避免中文路径下消息生成的历史问题。消息包采用复制安装，随后复制到工程的 overlay；不要改成 symlink install。

```bash
set +u
source /opt/ros/humble/setup.bash
export BAO_ROOT="$HOME/桌面/bao"
export BAO_MSG_BUILD="$HOME/bao_px4_msgs_migration"
mkdir -p "$BAO_MSG_BUILD/src"
cp -a "$BAO_ROOT/px4_msgs_overlay_ws/src/px4_msgs" "$BAO_MSG_BUILD/src/"
cd "$BAO_MSG_BUILD"
colcon build --merge-install --packages-select px4_msgs

# 仅在新机器，将搬来的旧产物改名留存。
if [ -d "$BAO_ROOT/px4_msgs_overlay_ws/install" ]; then
  mv "$BAO_ROOT/px4_msgs_overlay_ws/install" \
    "$BAO_ROOT/px4_msgs_overlay_ws/install.before-migration-$(date +%s)"
fi
mkdir -p "$BAO_ROOT/px4_msgs_overlay_ws/install"
rsync -a "$BAO_MSG_BUILD/install/" "$BAO_ROOT/px4_msgs_overlay_ws/install/"
source "$BAO_ROOT/px4_msgs_overlay_ws/install/setup.bash"

cd "$BAO_ROOT/uav_competition_ws"
for item in build install log; do
  if [ -d "$item" ]; then mv "$item" "$item.before-migration-$(date +%s)"; fi
done
colcon build --symlink-install --packages-select uav_competition
```

上面按首次迁移写；重复构建使用已有英文构建目录，不要反复 cp 导致目录嵌套。消息安装主要用于 Bash 启动流程，英文构建目录先保留以便排查。

如果用户名或工程位置变化，三个 `launch/px4_{regions,sensors,hover}.launch.py` 中的日志默认目录仍是 `/home/jiaxintang/桌面/bao/logs/flight`，需要改成新路径，再构建业务包。当前启动脚本大多从自身位置推导工程目录。

### 4.2 Agent

同样 Ubuntu 22.04 x86_64 的完整目录迁移，可以先检查已有 Agent：

```bash
cd "$HOME/桌面/bao"
LD_LIBRARY_PATH="$PWD/Micro-XRCE-DDS-Agent/install/lib" \
  ldd Micro-XRCE-DDS-Agent/install/bin/MicroXRCEAgent
```

没有 `not found` 后可以试用 `./scripts/run_xrce_agent.sh`。这只是动态库检查，最终仍需验证 DDS 连接。若需重编译，在新终端运行：

```bash
cd "$HOME/桌面/bao"
cmake -S Micro-XRCE-DDS-Agent -B Micro-XRCE-DDS-Agent/build_migration \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX="$PWD/Micro-XRCE-DDS-Agent/install" \
  -DUAGENT_SUPERBUILD=ON -DUAGENT_P2P_PROFILE=OFF \
  -DUAGENT_USE_SYSTEM_LOGGER=ON
cmake --build Micro-XRCE-DDS-Agent/build_migration -j2
cmake --install Micro-XRCE-DDS-Agent/build_migration
```

此构建可能联网获取 Fast CDR 2.2.x、Fast DDS 2.14.x 和 foonathan memory。当前成功环境的实际动态库为 Fast CDR 2.2.8、Fast DDS 2.14.7；仓库配置使用浮动分支，未来重建结果可能不同。已有依赖下载在旧 Agent build 下，另建构建目录不会自动复用它们；网络慢时保留原下载，不要反复删除重新下载。不要把 Agent 的 Fast DDS 库全局写入系统 ROS 的 LD_LIBRARY_PATH，启动脚本只给 Agent 设置本地库路径。

### 4.3 PX4 与 Gazebo 插件

在新机器第一次编译前，将旧缓存改名，不删除源码和 Git 元数据：

```bash
cd "$HOME/桌面/bao/PX4-Autopilot"
if [ -d build ]; then mv build "build.before-migration-$(date +%s)"; fi
source /opt/ros/humble/setup.bash
DONT_RUN=1 make -j2 px4_sitl gazebo-classic
```

`DONT_RUN` 表示只编译，不是启动错误。第一次构建仍可能下载 PX4 的外部依赖，只有复制整个现有虚拟机才能避免大部分重新安装和构建。

## 5. 图形检查与启动

```bash
gazebo --version
glxinfo -B
```

Gazebo 要有能正常工作的 OpenGL。虚拟机通常使用虚拟显卡，不要照搬旧机器的 NVIDIA 驱动，也不要直接固定旧的 DISPLAY 或 XAUTHORITY。若 GUI 卡死，先检查虚拟机 3D 加速和 `logs/simulation/gzclient.log`。

完成构建后，四个终端分别运行（保持打开）：

```bash
# 终端 1
cd "$HOME/桌面/bao"
./scripts/run_xrce_agent.sh
```

```bash
# 终端 2
cd "$HOME/桌面/bao"
./scripts/run_px4_competition.sh
```

```bash
# 终端 3，先验证已成功的左路线；右路线改为 route:=right
cd "$HOME/桌面/bao"
./scripts/run_px4_regions.sh route:=left
```

```bash
# 终端 4
cd "$HOME/桌面/bao"
./scripts/start_mission_when_ready.sh
```

迁移验收看实际日志：Gazebo 中看得到 Iris、TCP 4560 建连、DDS 有输出、传感器 READY、解锁起飞、依次完成区域、落地自动上锁、任务 COMPLETE。服务返回 success 只代表受理请求。新环境左右路线分别完成一趟后再认定迁移通过。

## 6. 无网络的情况

完整 `bao` 是项目备份，不是离线系统安装包。新系统离线安装还需要 ROS/Gazebo 及其全部 apt 依赖、Python wheels、构建下载缓存。最可靠的离线迁移方式是导出已验证的整台虚拟机；如果必须新装系统，先在同版本联网环境准备并验证离线依赖包，再搬到目标机。
