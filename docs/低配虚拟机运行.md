# 低配虚拟机运行

低配入口：`./scripts/run_px4_vm.sh`。目标是让 2 vCPU、4 GB 内存的 Ubuntu 22.04 x86_64 虚拟机有条件进行验证；这不是已验证的最低硬件要求。宿主机性能、虚拟显卡及 3D 加速影响很大，当前未在目标虚拟机实测 CPU、内存和完整飞行。

## 优化内容

| 项目 | 原配置 | VM 配置 |
|---|---|---|
| 物理更新 | 1000 Hz / 1 ms | 250 Hz / 4 ms，PX4 Classic 支持的锁步配置 |
| 光流相机 | 60 帧/秒 | 20 帧/秒，保留插件需要的 64×64 灰度图 |
| 原始光流输出 | 20 Hz | 10 Hz |
| 水平雷达 | 360 束 × 15 Hz | 180 束 × 10 Hz，仍覆盖 360°、最远 15 m |
| Gazebo 真值 | 20 Hz | 10 Hz |
| 飞机外观 | STL/DAE 网格 | 方块机身、机臂及四片可转动桨叶 |
| 阴影 | 开启 | 关闭，去掉网格及原点装饰 |
| 界面 | 默认帧率/窗口 | 15 FPS、初始 960×640、关闭立体渲染 |
| 光流 ROS 图像预览 | 可订阅 | 关闭额外发布，相机继续给真实光流插件供图 |
| 构建 | 默认并行 | 默认 1 个编译任务，包括嵌套 Gazebo 插件编译 |
| OpenCV/BLAS 计算线程 | 默认 | 启动入口限制为 1 |

这些是**工作量配置的减少**，不能直接当成实测 CPU 降幅。PX4 仍须进行估计和控制，Ubuntu 桌面和 ROS 节点也有固定开销，不能承诺 1 核或 2 GB 内存仍可稳定运行全套图形仿真。

场景按原 world 和原无人机模型每次生成到 `logs/simulation/vm_course.world`，不维护第二份手工地图。墙体位置、碰撞盒、双路线坐标、机体惯量、碰撞体、桨叶关节及电机插件保留。无人机为方块简化外观，质量和动力学参数不变。新视觉更轻，但碰撞响应及控制精度仍需试飞验证。

自检、传感器断流、走廊偏离、越界和超时保护继续执行。仿真速度保持 1 倍，控制节点继续 20 Hz；未通过降低模拟速度或放宽保护来隐藏算力不足。如果 CPU 仍跟不上且 RTF 持续明显低于 1，任务可能正常触发超时保护。

## 首次准备

新虚拟机先按《虚拟机迁移与依赖安装》装依赖并构建 PX4/消息。完整桌面 ROS 工具不是运行必要条件，低配新系统可安装 `ros-humble-ros-base` 和所列 Gazebo ROS 包，不必启动 RViz、QGroundControl 等额外程序。

GUI 限帧插件在低配启动时自动用本机 CMake/Gazebo/Qt 开发库编译，通常无需单独操作；这不是新增需要下载的外部源码。首次 PX4 编译也比已编译后的启动更耗内存。

本机已有工程只需要重新构建业务包一次，让启动参数生效：

```bash
cd "$HOME/桌面/bao"
set +u
source /opt/ros/humble/setup.bash
source "$PWD/px4_msgs_overlay_ws/install/setup.bash"
cd uav_competition_ws
CMAKE_BUILD_PARALLEL_LEVEL=1 colcon build --symlink-install \
  --executor sequential --packages-select uav_competition
```

虚拟机桌面分辨率建议 1280×720 左右，Gazebo 保持小窗口。开启虚拟机 3D 加速和对应增强工具。不要一开始强制使用软件 OpenGL，它可能增加 CPU 负担；先用 `glxinfo -B` 检查驱动。

## 完整启动命令

四个终端按顺序运行，每个保持打开。与原流程只需将仿真入口换成 `run_px4_vm.sh`。

```bash
# 终端 1：通信
cd "$HOME/桌面/bao"
./scripts/run_xrce_agent.sh
```

```bash
# 终端 2：低配仿真及 PX4
cd "$HOME/桌面/bao"
./scripts/run_px4_vm.sh
```

看到 `VM profile: physics=250 Hz...` 表示低配入口生效。界面限帧加载日志可查看：

```bash
rg 'VM GUI render limit|Error|Err' "$HOME/桌面/bao/logs/simulation/gzclient.log"
```

```bash
# 终端 3：左路线；右路线改 route:=right
cd "$HOME/桌面/bao"
./scripts/run_px4_regions.sh route:=left
```

```bash
# 终端 4：自检 READY 后开始
cd "$HOME/桌面/bao"
./scripts/start_mission_when_ready.sh
```

首次运行先验证起飞、巡航和接地上锁，分别完成左右路线后才能确认这台虚拟机适配成功。业务节点日志现在由启动脚本传入工程内 `logs/flight`，用户名变化不再写入旧用户名目录。

## 还需要进一步省资源

不要求显示画面时，终端 2 可以用：

```bash
cd "$HOME/桌面/bao"
HEADLESS=1 ./scripts/run_px4_vm.sh
```

这会省掉 gzclient 进程，但真实光流相机仍需图形渲染环境，不能把它理解为完全不需要 OpenGL。该模式没有比赛画面可录，适合调试。

给新虚拟机保留适量交换空间可以降低编译时被 OOM 杀死的概率，但换页不能提升飞行性能；持续换页时应先关闭浏览器、RViz 和其他占内存程序。不要同时运行悬停和巡航控制节点。

## 把运行数据发回来

在仿真和任务都运行时，新开终端执行：

```bash
cd "$HOME/桌面/bao"
mkdir -p logs/simulation
{
  date
  lscpu
  free -h
  ps -eo pid,comm,pcpu,pmem,rss --sort=-pcpu | head -20
  timeout 15s gz stats -d 10 -p
} 2>&1 | tee logs/simulation/vm-performance.txt
```

发回 `vm-performance.txt`、巡航终端日志，以及 `gzclient.log` 中限帧行。`ps` 的 CPU 是进程启动以来平均值，RSS 单位为 KiB；`gz stats` 用来判断是否接近实时运行。当前只完成场景 SDF 检查、GUI 插件编译、碰撞/动力学保留检查和双路线规划测试，尚无目标虚拟机性能数字。


双路线、真实传感器、自检和安全保护继续保留。编译及 9 项检查通过，实际性能和飞行还需在虚拟机验证，可先试 2 核、4 GB。
