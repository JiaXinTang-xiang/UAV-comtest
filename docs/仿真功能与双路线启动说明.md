## 1. 当前环境和功能

| 项目 | 当前实现 |
|---|---|
| 仿真平台 | Ubuntu 22.04、Gazebo Classic 11、PX4 SITL、ROS2 Humble |
| 通信 | Micro XRCE-DDS Agent，PX4 原生 ROS2 话题，无需 MAVROS |
| 场景 | 10 m × 10 m 训练地图、隔离墙、区域标识、起降区；Iris 随世界文件直接加载 |
| 遥测 | PX4 位姿、速度、IMU、电量、图像光流、向下测距，以及 Gazebo 水平激光扫描 |
| 自检 | 校验数值、时间戳更新、新鲜度、光流质量、测距质量、电量有效性和雷达扫描结构 |
| 起飞 | 手动请求任务后，预发送 Offboard 心跳、切换模式、自动解锁并爬升到 2.5 m |
| 区域任务 | 可选择右路线或左路线，依次经过区域 2 → 3 → 4 → 5，再飞向降落区 |
| 路径规划 | 根据世界文件碰撞墙体进行 A* 规划及直线可见性简化；控制节点限制位置参考变化速度 |
| 动态规划 | 雷达未知障碍加入规划；规划失败先悬停，每隔 1 秒重试，连续规划等待上限 15 秒 |
| 安全保护 | 传感器/控制指令断流、围栏越界、走廊偏离、任务超时、近距离障碍和持续无路可走触发保护 |
| 降落 | 到达配置的降落坐标附近后请求 PX4 LAND，确认接地和自动上锁，再报告 COMPLETE |
| 记录 | 控制台日志、任务 JSON、飞行 CSV、飞控结果 JSON、Gazebo 日志及 PX4 ULog |

光流来自仿真相机图像，激光数据来自 Gazebo ray，电量来自 PX4 仿真电池。Gazebo 真值单独记录，不输入任务控制。

## 3. 完整启动命令

每组命令在一个独立终端中运行。启动脚本会加载所需环境，无需先手动 source ROS2，也无需手动设置 DISPLAY。

启动区域巡航时，不要同时运行悬停控制脚本，两者使用相同的控制话题。

### 终端 1：通信代理

```bash
cd /home/jiaxintang/桌面/bao
./scripts/run_xrce_agent.sh
```

代理已在运行时保留原终端，不重复启动。若端口 8888 被占用，可先检查：

```bash
pgrep -af MicroXRCEAgent
```

### 终端 2：Gazebo 场景和 PX4

```bash
cd /home/jiaxintang/桌面/bao
./scripts/run_px4_competition.sh
```

正常启动会依次看到：

```text
Not running simulation (DONT_RUN is set).
Waiting for Gazebo world and Iris MAVLink interface...
Gazebo world and Iris are ready; MAVLink TCP 4560 is up.
px4 starting.
Simulator connected on TCP port 4560.
Ready for takeoff!
```

`DONT_RUN` 是脚本先单独编译时的正常提示；随后脚本自行启动世界和 PX4。

### 终端 3：选择一条路线

**右路线：**

```bash
cd /home/jiaxintang/桌面/bao
./scripts/run_px4_regions.sh route:=right 2>&1 | tee logs/right_route_clean.log
```

**左路线：**

```bash
cd /home/jiaxintang/桌面/bao
./scripts/run_px4_regions.sh route:=left 2>&1 | tee logs/left_route_clean.log
```

左右命令每次只选一条。等待飞行状态 `WAITING -> READY` 和自检 `READY`；节点此时不会自行解锁。

### 终端 4：开始所选任务

```bash
cd /home/jiaxintang/桌面/bao
./scripts/start_mission_when_ready.sh
```

服务返回 `success=True` 表示任务请求已受理；飞行是否完成应看终端 3 的状态和结果文件。

正常过程：

```text
flight READY -> PRIMING -> SET_MODE -> ARM -> TAKEOFF -> ACTIVE
mission ... -> AREA_2 -> AREA_3 -> ... -> AREA_4 -> AREA_5
mission AREA_5 -> LAND_APPROACH -> LANDING -> COMPLETE
flight ACTIVE -> LANDING -> COMPLETE
```

任务经过 TRANSIT 航段时会额外打印对应状态。

## 4. 两次完整飞行与关闭顺序

训练安排可按第一趟右路线、第二趟左路线执行；正式比赛的机会次数以赛方规定为准。

1. 第一趟按上述流程选 `route:=right`。
2. 确认任务 COMPLETE、飞机落地上锁，再在终端 3 按 Ctrl+C 关闭巡航节点。
3. 在终端 2 按 Ctrl+C 关闭本趟仿真，保留终端 1 的 Agent。
4. 重新运行终端 2，恢复到初始起飞点。
5. 重新运行终端 3，选择 `route:=left`。
6. 运行终端 4 的开始命令。

不能仅在已完成任务的节点上再次调用 start，也不能仅重启巡航节点后把降落位置当作初始起飞点。

需要主动结束空中任务时，可在新终端请求降落：

```bash
set +u
source /opt/ros/humble/setup.bash
ros2 service call /uav/flight/land std_srvs/srv/Trigger '{}'
```

该服务表示在当前位置降落，不会自动飞回靶标。落地上锁后再关闭节点。

## 6. 配置和源码入口

- `uav_competition_ws/src/uav_competition/config/mission.yaml`：路线、区域坐标、速度、规划余量和超时等。
- `uav_competition_ws/src/uav_competition/worlds/competition_course.world`：训练地图、墙体碰撞和 Iris 初始位置。
- `uav_competition_ws/src/uav_competition/uav_competition/px4_region_mission.py`：区域任务、雷达障碍记忆、悬停重规划和任务日志。
- `uav_competition_ws/src/uav_competition/uav_competition/path_planner.py`：墙体解析、碰撞校验和 A* 规划。
- `uav_competition_ws/src/uav_competition/uav_competition/px4_offboard_node.py`：PX4 模式、解锁、位置控制接口、遥测和降落确认。
- `uav_competition_ws/src/uav_competition/uav_competition/preflight_check.py`：传感器有效性自检。

区域巡航实际读取 `route_profiles.<路线>.targets`；维护时同时同步 `mission.route`，避免其他启动方式读取到旧坐标。修改配置或源码后需重新构建并重启巡航节点。
